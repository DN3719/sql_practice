# Git 入门速查（新手版）

## 一句话理解

Git 就是一个"存档 + 时光机"工具：每当你对代码/文档的改动满意了，就拍一张照（`commit`），以后随时可以回到任何一张照片。照片存在本地电脑上，也可以传到服务器（`push`），别人更新了再拉回来（`pull`）。

## 三个区域（最核心的概念）

| 区域 | 是什么 | 对应动作 |
| --- | --- | --- |
| 工作区 | 你正在编辑的文件 | 直接改 |
| 暂存区 | 改好了、准备拍照的内容 | `git add` |
| 本地仓库 | 已经拍好的照片（历史记录） | `git commit` |

完整流程：

```
改文件 → git add → git commit → git push（传到远程）
                ↑ 这三个动作会反复用
```

## 最常用的 8 条命令

```bash
git status              # 看当前状态：改了哪些文件、有没有待提交的
git add 文件名          # 把某个文件放进暂存区
git add .               # 把当前目录所有改动放进暂存区
git commit -m "说明文字" # 拍照存档，说明文字写清这次干了啥
git push                # 把本地照片传到远程仓库（服务器）
git pull                # 把远程最新内容拉下来
git clone 仓库地址       # 第一次从远程把整个项目复制到本地
git log --oneline       # 看历史记录（每一行是一张照片）
```

## 新手最容易犯的错 & 补救

| 场景 | 命令 | 注意 |
| --- | --- | --- |
| 提交完了发现说明写错了 | `git commit --amend -m "新说明"` | 只改最后一次提交 |
| 发现改了不该改的文件，想还原 | `git checkout -- 文件名` | ⚠️ 改动会丢失，不可恢复 |
| 改到一半想先拉最新代码 | `git stash`（存起来）→ `git pull` → `git stash pop`（取回来） | 临时收藏夹 |
| 提交漏了一个文件 | `git add 漏掉的文件` → `git commit --amend` | 补进上一次提交 |
| 想看看改了什么再提交 | `git diff` | 只看未暂存的改动 |

## Windows 上怎么打开

- 开始菜单搜索 **Git Bash**（推荐新手用，命令提示符风格更像 Linux）
- 或者直接开 **PowerShell / CMD**（新窗口才有 git 命令），在任意文件夹里输 `git status` 试试

## 实际例子：更新 DeepSeek Harness

以后官方更新了想拉新版：

```bash
cd E:\deepseek-harness
git pull
```

前提是该文件夹是用 `git clone` 拉下来的（现在这份是手动下载的 zip，不是 git 仓库，所以要先删掉重新 clone 一次，或者新建文件夹 clone）。

## 重要提醒

- 每次 commit 前先 `git status` 看一眼，确认没有把不想提交的文件带进去
- 说明文字（`-m`）要写清楚，别写"改了一下"，以后你自己都看不懂
- 涉及密钥、密码、数据库账号的配置文件**永远不要提交**（先学会 .gitignore 再说）
