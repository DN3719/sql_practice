# 创建"非空索引"（只索引非 NULL 的行）

> 场景：某列大量值为 NULL，只有少数行有值，想建索引又不想把 NULL 也塞进索引，减小索引体积、降低写入维护成本。

## 1. 先说结论

- **PostgreSQL**：原生支持部分索引（partial index），可以直接"只索引非 NULL 的行"。
- **MySQL**：不支持部分索引，普通索引会把 NULL 也索引进去，没有官方语法能排除 NULL 行，只能靠数据治理（不存 NULL）近似解决。

## 2. PostgreSQL 写法

```sql
CREATE INDEX idx_users_phone ON users (phone) WHERE phone IS NOT NULL;
```

特点：

- 只有 `phone IS NOT NULL` 的行进索引，索引体积小、DML 维护成本低
- 查询条件 `WHERE phone = '13800138000'` 会被优化器推导为满足 `phone IS NOT NULL`，也能命中该索引，不需要额外加条件
- 删除索引：`DROP INDEX idx_users_phone;`

验证是否走索引：

```sql
EXPLAIN SELECT id FROM users WHERE phone = '13800138000';
```

输出中出现 `Index Scan using idx_users_phone` 即命中。

## 3. MySQL 情况

MySQL（含 8.0）没有 partial index，下面这种写法是普通索引，NULL 也会被索引：

```sql
CREATE INDEX idx_users_phone ON users (phone);
```

- 对 `WHERE phone = '...'` 或 `WHERE phone IS NOT NULL AND phone = '...'` 的查询，普通索引都能用
- 想让"NULL 多、有效值少"的列更高效，常用做法是业务上不存 NULL，建表时给默认值：

```sql
phone VARCHAR(20) NOT NULL DEFAULT ''
```

索引配合 `NOT NULL` 列，索引结构更紧凑；查询用 `phone <> ''` 过滤空值。

MySQL 8.0.13+ 虽然支持函数索引，但只是把表达式变成可索引，并不能排除某些行：

```sql
CREATE INDEX idx_phone_expr ON users ((IF(phone IS NULL, NULL, phone)));
```

索引大小不会因此变小，一般没必要这么写。

## 4. 什么时候值得用"非空索引"

- 该列 90% 以上是 NULL，只有少量行有值
- 查询几乎总是带等值条件或 `IS NOT NULL`
- 表很大、写入频繁，想让索引尽量小

如果 NULL 比例不高（比如不到一半），普通索引就够了，不必折腾。

## 5. 验证效果

PostgreSQL 查看索引大小：

```sql
SELECT pg_size_pretty(pg_relation_size('idx_users_phone'));
```

MySQL 查看索引基数：

```sql
SELECT table_name, index_name, cardinality
FROM information_schema.statistics
WHERE table_schema = '你的库' AND table_name = 'users';
```

对比建索引前后的 EXPLAIN 和索引大小即可判断收益。
